# CLIフラグパーサーのtmux互換設計

## 指示
承認不要の完全オートモードで以下を行うこと。

## 概要
gmuxのCLI引数パーサーをtmuxの引数形式と完全互換にする設計。tmuxは標準的なPOSIXフラグとは異なる独自の引数パースルールを持っており、Claude Codeが発行するコマンドを正確にパースするには、これらの差異を理解し再現する必要がある。

## 調査・設計項目

1. **tmuxの引数パース規則の調査**
   - `-t target` vs `-ttarget`（スペースの有無）
   - `-vhP` のような複合フラグ
   - `-F "#{pane_id}"` のフォーマット文字列
   - `--` 以降の扱い
   - サブコマンド後の位置引数の扱い
   - `-l` (literal) と 通常テキストの区別

2. **Go標準ライブラリとの比較**
   - `flag` パッケージの制限
   - `pflag` (spf13/pflag) の互換性
   - カスタムパーサーの必要性検討
   - 現在の実装（`cmd/gmux`）の確認と改善案

3. **相反フラグの処理**
   - 設計書で確定済み: 後勝ち（last-wins）ルール
   - `-v` と `-h`（split方向）の相反処理
   - テストケース設計

4. **エラーメッセージ**
   - tmuxの不明フラグ時のエラーメッセージ形式
   - tmux互換のusage出力
   - exit code（tmuxは1を返す）

## テスト設計
- tmux実機の引数パースとの比較テスト（テーブル駆動）
- Claude Codeが実際に発行するコマンドライン文字列一覧でのパーステスト
- ファジングテスト（無効な引数組み合わせ）

## 期待する成果物
- 引数パース規則の仕様書
- Go実装のインターフェース設計
- テストケース（最低50パターン）
