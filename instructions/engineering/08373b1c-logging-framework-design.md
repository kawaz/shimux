# ログフレームワーク設計と実装

## 指示
承認不要の完全オートモードで以下を行うこと。

## 概要
gmuxのログ出力方針は設計書で定義済み（UTC Timestamp、ローカル日付ファイル名、書き込み失敗時はstderr警告）。これを実装するためのログフレームワークの詳細設計と、Goの標準ライブラリ `log/slog` を活用した実装方針を策定する。

## 設計項目

1. **slogベースのログ設計**
   - `log/slog` のStructured Loggingを活用
   - ログレベル: DEBUG, INFO, WARN, ERROR
   - 環境変数 `GMUX_LOG_LEVEL` でレベル制御
   - デフォルトレベル: INFO

2. **出力先管理**
   - ファイル出力: `~/.local/state/gmux/logs/YYYY-MM-DD.log`（ローカル日付）
   - stderr出力: ログファイル書き込み失敗時のフォールバック
   - `--debug` フラグでstderrにも同時出力
   - ファイルローテーション: 古いログの自動削除（保持日数設定）

3. **構造化ログのフィールド**
   - `timestamp`: UTC（RFC3339、末尾Z）
   - `level`: ログレベル
   - `component`: gmux / gmux-agent / keysim
   - `session`: セッション名
   - `pane_id`: ペインID（該当する場合）
   - `command`: 実行中のtmuxコマンド
   - `msg`: メッセージ

4. **パフォーマンス考慮**
   - 非同期書き込み（バッファリング）の検討
   - ホットパス（send-keys）でのログレベルチェック最適化
   - ベンチマークでのオーバーヘッド測定

## テスト設計
