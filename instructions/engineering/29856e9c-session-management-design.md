# セッション管理の詳細設計

## 指示
承認不要の完全オートモードで以下を行うこと。
この指示による新規ドキュメント作成は `docs/drafts/` 配下に限定。既存ファイル編集・コード新規作成は通常通り。

## 概要
gmuxのセッション管理（new-session, has-session, kill-session, list-sessions）の詳細設計。Claude Codeはセッション名を使ってtmux環境を管理するため、セッション概念の正確な再現が必要。

## 設計項目

1. **セッション概念のマッピング**
   - tmuxセッション ≒ Ghosttyウィンドウ（or タブ？）の対応関係
   - セッション名の永続化（状態ファイル内のトップレベルキー）
   - セッション名の正規化ルール（`[^a-zA-Z0-9-]` → `_`）
   - 複数セッションの同時管理

2. **new-session**
   - Ghostty新ウィンドウの作成 vs 既存ウィンドウの再利用
   - `-d`（デタッチ）フラグの意味合い
   - `-s session-name` でのセッション名指定
   - `-x width -y height` でのサイズ指定
   - 既存セッション名の重複チェック

3. **has-session**
   - セッション存在確認の実装方法
   - exit code: 0（存在）/ 1（不存在）
   - 状態ファイルとプロセスの両方を確認する必要性

4. **kill-session**
   - 全ペインのgraceful shutdown
   - ソケット・PIDファイルのクリーンアップ
   - 状態ファイルからのエントリ削除
   - Ghosttyウィンドウの閉じ方

5. **list-sessions**
   - 出力フォーマット（tmux互換: `session_name: N windows ...`）
   - `-F` フォーマット文字列のサポート範囲

## テスト設計
- セッション作成→確認→削除のライフサイクルテスト
- 重複セッション名の処理テスト
- orphanedセッションの検出テスト
