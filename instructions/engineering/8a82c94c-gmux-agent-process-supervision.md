# gmux-agentプロセス監視設計

## 指示
承認不要の完全オートモードで以下を行うこと。

## 概要
gmux-agentプロセスが各ペインで正常に動作し続けることを保証するプロセス監視の仕組みを設計する。異常終了の検出、orphanedプロセスのクリーンアップ、ヘルスチェック機構を含む。

## 設計項目

1. **プロセス監視の仕組み**
   - gmux-agentの起動検知（ソケット接続ポーリング vs inotify的な仕組み）
   - heartbeat/keepalive（ソケット経由のping-pong）
   - PIDファイル管理（状態ファイルに含めるか別管理か）
   - `os.Process.Signal(0)` によるプロセス生存確認

2. **異常終了の検出と対応**
   - gmux-agentがSIGKILL/SIGSEGVで死んだ場合
   - ソケットは残るがプロセスは消えたケース
   - 内部PTY子プロセス（zsh）が先に死んだケース
   - 検出後のステート更新（`dead`/`orphaned`への遷移）

3. **ヘルスチェックコマンド**
   - `gmux health` or `gmux doctor` の設計
   - チェック項目:
     - 全登録ペインのプロセス生存確認
     - ソケット接続性テスト
     - 状態ファイルと実プロセスの整合性
     - staleソケットの検出
   - 出力形式: 人間用テーブル + JSON（`--json`フラグ）

4. **自動リカバリー**
   - staleソケット・PIDエントリの自動削除
   - orphanedペインの再接続可否
   - `gmux cleanup` コマンドでの手動トリガー

## テスト設計
- プロセス強制終了後のヘルスチェック挙動テスト
- 並行kill+healthの安全性テスト
- staleソケット生成→cleanup→状態確認のE2Eテスト

## 期待する成果物
- プロセス監視設計書
- `gmux health`/`gmux cleanup` のコマンド仕様
- テストケース一覧
