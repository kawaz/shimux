# Unixソケット通信プロトコルの詳細設計

## 指示
承認不要の完全オートモードで以下を行うこと。

## 概要
gmux-agentとgmuxコマンド間のUnixソケット通信プロトコルを詳細に設計する。メッセージ形式、エラーハンドリング、バージョニング、後方互換性を考慮した堅牢なプロトコルを定義する。

## 設計項目

1. **メッセージフレーミング**
   - 長さプレフィックス vs デリミタ vs 固定長ヘッダ
   - バイナリ vs テキスト（JSON）
   - 最大メッセージサイズの制限

2. **リクエスト/レスポンス形式**
   - send-keys: テキストデータの送信
   - capture-pane: ペイン内容の取得
   - ステータス問い合わせ（alive?）
   - graceful shutdown要求

3. **エラーコード体系**
   - プロトコルエラー（不正なフレーム等）
   - アプリケーションエラー（ペインが存在しない等）
   - リトライ可能 vs 致命的の分類

4. **バージョニング**
   - ハンドシェイク時のバージョンネゴシエーション
   - 後方互換性ポリシー
   - 非互換変更時の挙動

5. **セキュリティ考慮**
   - ソケットファイルのパーミッション（0700）
   - 認証トークンの必要性
   - 不正クライアントからの防御

## 参考プロトコル

- Docker API（Unix socket over HTTP）
- kittyのremote control protocol
