# 並行アクセスストレステスト設計

## 指示
承認不要の完全オートモードで以下を行うこと。

## 概要
gmuxのPTYプロキシとペイン状態管理が並行アクセスに耐えるかをテストする設計を行う。Claude Code Agent Teamsは複数エージェントが同時にtmuxコマンドを発行するため、これは実用上不可欠。

## テストシナリオ

1. **同時split-window**
   - 5エージェントが同時にsplit-windowを発行
   - ペインIDの一意性が保証されるか
   - 状態ファイルのrace condition

2. **同時send-keys**
   - 同一ペインへの同時書き込み
   - 異なるペインへの同時書き込み
   - ソケット接続の排他制御

3. **split + kill の競合**
   - split-window中にkill-paneが発行された場合
   - kill中にsend-keysが発行された場合
   - 存在しないペインへの操作

4. **状態ファイルの整合性**
   - ファイルロック機構の設計
   - クラッシュ後のリカバリー
   - staleエントリの検出と自動削除

5. **負荷テスト**
   - 100ペイン同時運用
   - 1秒あたり100回のsend-keys
   - メモリリーク検出

## 実装方針
- `go test -race` による race condition 検出
- `sync.WaitGroup` を使った並行テスト
- `-count=100` での繰り返し実行
