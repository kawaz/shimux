# パフォーマンスベンチマークスイートの構築

## 指示
承認不要の完全オートモードで以下を行うこと。

## 概要
gmuxの各操作のパフォーマンスを測定するベンチマークスイートを構築する。tmuxとの比較データを取得し、許容範囲内であることを確認する。

## ベンチマーク対象

1. **起動時間**
   - `gmux` コマンドの起動からexit（no-op）まで
   - 目標: 10ms以下（Go binary cold start）
   - 比較: `tmux` の同等操作

2. **split-window レイテンシ**
   - コマンド発行から新ペイン表示まで
   - System Events keysimの遅延
   - 目標: 500ms以下（人間が知覚できるギリギリ）

3. **send-keys スループット**
   - 1文字送信のレイテンシ
   - 大量テキスト（1KB, 10KB, 100KB）の転送時間
   - Unixソケット経由のオーバーヘッド測定
   - 比較: tmux send-keysとの差

4. **list-panes レスポンス**
   - ペイン数（1, 5, 10, 20）ごとのレスポンス時間
   - JSON状態ファイル読み取りのオーバーヘッド

5. **メモリ使用量**
   - gmux-agentプロセス1個あたりのメモリ
   - ペイン数増加に伴うメモリ増加率
   - 長時間運用時のメモリリーク検出

## 実装方針
- `go test -bench` を使用
- `testing.B` でのベンチマーク
- 結果をJSON出力し、`benchstat`で比較分析
- CI連携でリグレッション検出

## 期待する成果物
- ベンチマークコード（`*_bench_test.go`）
- 実行結果のベースライン記録
- パフォーマンス要件ドキュメント
