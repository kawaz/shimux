# DR-004: PoC 成果の取り扱い

## 問題/背景

AppleScript 対応による設計転換 (DR-001) により、PoC フェーズのコードと設計書の大部分が現行設計と乖離した。
これらの資産をどう扱うかを決定する必要がある。

## 決定内容

### archive@ ブランチへの移動

以下を全て `archive@` ブランチに移動:

- **poc001-go**: Go による初期 PoC（tmux コマンドパース、ペイン管理）
- **poc002-pty-proxy**: MoonBit + Rust FFI による PTY プロキシ PoC
- **poc003-tty-overlay**: TTY オーバーレイ PoC
- **旧設計書**: docs/design.md 等の AppleScript 以前の設計ドキュメント

### 残すべき知見

PoC で得た以下の知見は現行設計にも有効であり、新しい設計ドキュメントに引き継ぐ:

- **tmux コマンド互換性の要件**: Claude Code が発行する tmux コマンドのリスト
- **tmux CLI のパース仕様**: サブコマンド構成、オプション体系
- **ペイン状態管理のモデル**: ID 管理、ツリー構造

## 選択理由/トレードオフ

### archive@ ブランチを選択した理由

- main ブランチをクリーンに保ちつつ、PoC の履歴を完全に保存
- 必要時に参照可能（`jj log -r archive@` や `jj diff -r archive@`）
- 削除ではなくアーカイブなので、知見の喪失リスクがない

### 不採用の選択肢

- **main に残す**: 現行設計と乖離したコードが混在し、混乱を招く
- **完全削除**: PoC の知見（特に tmux 互換性の調査結果）が失われる
- **別リポジトリ**: 管理が分散し、参照が面倒

## 影響

- main ブランチは README.md + LICENSE のみのクリーンな状態からスタート
- PoC の知見は必要に応じて archive@ から参照し、新しい DR やソースコードに反映
